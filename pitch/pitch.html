01The problem

A new consultant asks the company AI how long client onboarding takes. It says four weeks, which is wrong. The target changed five times across meetings and reports, and the final report of 28 November 2025 says three to four weeks. The old figure from the final presentation is still in memory, and still active.

Today she opens a ticket and waits for an engineer to read the logs and the vector store [not verified]. Giulia, the operations lead, would know the right answer in ten seconds, but she cannot see what the AI believes, and she cannot change it.

56% of the 48,000 people surveyed say they made mistakes at work because of AI [verified: KPMG and University of Melbourne, 2025].

STEP 1Read: from documents to facts modelcode

Sources arrive through four doors: the project's documents, a versioned document library, a mailbox, and a webhook or upload for meeting notes and tickets. Each new item is read by Claude Haiku 5.5, which returns its facts as strict JSON. A fact is one sentence with a value, its type (a decision, a constraint, evidence, a hypothesis or an open question), the document it comes from, its date and the exact words it was taken from.

Then the code checks the model's work. If the quoted words are not found word for word in the document, the fact is discarded. The model cannot invent a source, and every fact on screen can be traced back to a sentence someone actually wrote.

In the example, the final presentation of 21 November yields "onboarding takes 4 weeks", and the final report of 28 November yields "3 to 4 weeks", each with its quote.

STEP 2Order: which version holds now modelcode

Claude Sonnet 5.5 groups the facts by topic, such as "onboarding time", and suggests which fact replaces which. These are only proposals. The code checks every link and puts the versions of a topic in date order, oldest first, so each topic becomes a history you can read.

The code then picks the one fact that binds for each topic. A fact that a person has pinned wins. Without a pin, the most recent active fact wins. A retired fact never binds. An old version that a newer one replaced stays in the history, struck through. If an old version was replaced but is still marked active, it goes to a maintenance queue so a person can retire it. When two sources state the same value, there is no conflict: the later one binds and the answer says the other one confirms it.

Onboarding has six versions. "3–4 weeks" from the final report binds. "4 weeks" from the final presentation was replaced but is still active, so it is flagged.

STEP 3Answer: built by code, with its source modelcode

A question is first matched to a topic. The code tries known phrasings first. If none fits, Claude Haiku 5.5 picks the topic from the list of topics, without seeing any document. If the model is slow or unavailable, the code falls back to keywords.

The answer itself is written by code from the facts, with no model. It gives the binding value with its quote, source and date. If two active facts disagree, the answer says the topic is contested and shows both. If the memory holds nothing on the question, it says so instead of guessing. When a person has corrected something, the answer adds "changed because…" with who did it and why.

Before the fix, the answer is "3–4 weeks", with a warning that "4 weeks" is still active in the memory.

STEP 4Correct: the people who know the facts fix them a personcode

The operations lead opens a fact and sees its sentence, its source, its date and the versions it replaced. From there she can retire it, restore it, pin the right one, correct a value, settle a conflict, or decide what the maintenance queue proposes (approve the retirement or keep the fact). She never sees a log file, an embedding or a similarity score.

Every action is written to an audit trail with who, when and why, and it can be undone. The change goes into the same memory the answers are built from, so the next answer uses it immediately. Nothing has to be retrained or re-indexed.

Giulia retires "4 weeks" with the reason "replaced by the final report". The same question now gets "3–4 weeks" with no warning, and the answer says it changed because Giulia retired the old figure.

The answer never comes from a model. Each fact on screen is a sentence quoted from a dated document, with no embeddings and no similarity scores. A conflict and "no answer in memory" are outcomes the user sees. New sources keep arriving through uploads, inbound webhooks, a mailbox and new versions of library documents, and each one extends the chain instead of overwriting it.

The demo path makes no model calls and also runs offline, so the venue Wi-Fi cannot break the core flow.

On the five benchmark questions where a decision changed over time, Canonico answers from the binding version 3 times out of 5. Plain retrieval over the same documents gets none.

The benchmark is the OIDA ClearPath set: 26 queries with graded judgments. The code is in eval/, and one command prints the score. Five questions are a small sample, since one question moves the number by 20 points. The weights were tuned on the same queries and there is no held-out set. Two of the five (q05, q06) still fail, and the repo says why.

Test with people outside the team. Three people who had never seen Canonico tried the live app today, and all three gave positive feedback [declared]. Three people are a first signal, not a measurement.

06Why us, why now

Mem0 raised $24M in October 2025 [verified: mem0.ai] and sells a memory layer to developers. Since April 2026 its open-source extraction only adds facts, so wrong and outdated ones pile up next to the right ones [verified: GitHub mem0ai/mem0]. Zep's Graphiti keeps facts with validity windows [verified: GitHub getzep/graphiti]. That is the right data model, but nobody outside engineering can open it and fix a fact. Letta's agents edit their own memory. Claude and ChatGPT let one person edit their own memory, with no sources and no view across the organisation [verified: Claude release notes] [declared: openai.com].

Canonico gives the organisation one view of what its AI believes, built for the people who know the facts, and a retire that provably changes the next answer. Summarising memory to save space destroyed 60% of stored facts in one 2026 preprint [verified: arXiv 2603.17781]. We keep every version with its source sentence instead.

07Adoption

A firm starts from the hosted link: it logs in, connects a project to its documents, a mailbox or a webhook, and the memory fills up. Forwarding an email or posting a meeting note to the project's webhook is enough to add a source. A firm that wants its data at home runs docker compose up from the public repo. Model calls go through one gateway key held on the server, with a spending cap on every run.

09Models and AI tools used

Inside the product, through the Vercel AI Gateway: Claude Haiku 5.5 extracts facts and routes free questions to a topic, and Claude Sonnet 5.5 groups facts into topics and proposes which fact replaces which; code checks every proposal. Answers are composed by code, with no model. Build and test runs used our own Anthropic API key, not the team key.

Used to build it: Claude Code (Claude Opus 5.5) for the backend, the interface, the research, the economic model and this pitch.
